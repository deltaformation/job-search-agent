# v1.3 B — Persistence and workspace API handoff for C, E, F, G

WO-1.3-B interface publication (2026-09-16). Migration 0008 is
applied, transaction W and the workspace/version reads are live,
and the repositories E/F/G compose are tested with isolated
fixtures. This document is the exact contract surface: signatures,
error names, budgets, and test evidence. Normative behavior stays
in `docs/tailoring-contracts-v1.3.md`.

## 1. Migration and schema

- `drizzle/0008_tailoring_workspaces.sql`: DDL verbatim from
  `docs/contracts/v1.3-0008.sql` (verified byte-identical from the
  first statement). Applies on fresh 0000→0008 and seeded
  0007→0008; reruns no-op; drift aborts.

  (`tailoringWorkspaces`, `tailoringRequestInputs`,
  `generationProgressEvents`, `resumeAssessments`) exported from
  `src/db/schema.ts`. Triggers stay SQL-only.
- Existing tables gained the seven 0008 unique indexes
  (`v13_extraction_owner`, `v13_profile_version_owner`,
  `v13_resume_owner`, `v13_one_version_per_request`,
  `v13_request_owner`, `v13_attempt_owner`,
  `v13_one_live_tailor`). Consequence: at most one QUEUED/RUNNING
  TAILOR item per non-null job; at most one version per request.
- `preflightTailoringUpgrade(sqlite, migrationsDir)` in
  `src/db/migrate.ts`, enforced by `ensureDatabase` before
  migrating: while 0008 is pending and TAILOR work is live, the
  upgrade throws an actionable error and changes/deletes nothing.
- `getTailoringJob` now also returns `selectedResumeVersionId`
  (additive; existing callers unaffected).
- Restore validation (`verifyStagedDatabase`): a staged DB with
  0008 applied must hold all four tables, and every staged DB must
  pass `PRAGMA foreign_key_check`, or the restore is refused
  before replacement. Reset needs no code change: rebuilds clear
  all job-owned rows (proven) while preserving candidate chains.

## 2. Repositories (`src/db/tailoringWorkspace.ts`)

All methods run in one short synchronous transaction
(nest-safe via `withTransaction`), take trusted service clocks
(`now: string`) and lease tuples as explicit parameters, store
JSON as text (services parse strictly), and let SQL trigger
names propagate as `SqliteError`:

| Method | Contract |
|---|---|
| `readWorkspace(handle, jobId)` | One PK lookup; `TailoringWorkspace \| null`. |
| `saveWorkspaceCAS(handle, input)` | Observed 0 inserts rev 1; else commits iff stored revision equals observed. Preserves `last_request_id`/`last_submitted_revision`. Returns `{ok, revision, created}` or `{ok:false, error:"conflict", currentRevision}`. |
| `markWorkspaceSubmitted(handle, {jobId, observedRevision, requestId, now})` | **E's G primitive.** CAS revision+1 and binds `last_request_id`/`last_submitted_revision` to the new revision. Same result shape as above. Never called by W. |
| `insertRequestInputs(handle, input)` | One immutable extension row. Cross-profile snapshots abort `INPUT_PROFILE_MISMATCH`; later UPDATE/DELETE abort `INPUT_IMMUTABLE`. |
| `readRequestInputs(handle, requestId)` | Raw extension row for re-verification. |
| `appendProgressFenced(handle, event)` | One boundary event under the live lease tuple. Lease/tuple/start violations abort `LEASE_LOST`; bad order aborts `PROGRESS_SEQUENCE_INVALID`; seq↔stage mismatch aborts `PROGRESS_STAGE_INVALID`; regressing timestamps abort `PROGRESS_TIME_INVALID`; source switches abort `PROGRESS_SOURCE_INVALID`; later UPDATE/DELETE abort `PROGRESS_IMMUTABLE`. |
| `insertAssessment(handle, input)` | One immutable assessment. Binding disagreement aborts `ASSESSMENT_BINDING_INVALID`; later UPDATE/DELETE abort `ASSESSMENT_IMMUTABLE`. |
| `readAssessment(handle, resumeVersionId)` | Raw assessment row; G parses measures strictly. |
| `readRequestProgress(handle, requestId)` | **F's read primitive.** At most 5 statements (request; work item; latest attempt; latest-attempt events; published version). Column-scoped: lease tokens, queue payloads, and steering JSON are never selected. Returns `null` for unknown requests and item-less rows. |

Trigger-error → HTTP mapping is each service's job; the names
above are the stable vocabulary (`LEASE_LOST`,
`INPUT_PROFILE_MISMATCH`, `INPUT_IMMUTABLE`,
`PROGRESS_*`, `ASSESSMENT_BINDING_INVALID`,
`ASSESSMENT_IMMUTABLE`, `WORKSPACE_REVISION_INVALID`).

## 3. Service (`src/server/tailoringWorkspace.ts`)

- `getWorkspaceView(handle, jobId)` → `{ok, value: {workspace:
  WorkspaceView \| null, revision, etag, created}}`. Absent
  workspaces return null at revision 0 **without inserting**.
  Exactly 2 statements. Corrupt stored JSON/timestamps →
  `storage-unavailable`.
- `saveWorkspace(handle, jobId, observedRevision, body:
  WorkspacePut, deps)` implements W: phase-1 build + hash +
  selection checks outside the transaction; phase-2 active-binding
  recheck + parent ownership + CAS inside one transaction. Never
  bumps the job version; never touches queue/review state.
  Failures: `unknown-job`, `not-found` (foreign/missing
  extraction, version, parent), `workspace-conflict`
  (+`currentWorkspaceRevision`), `input-stale` (+`field`),
  `invalid-selection` (+`field`), `storage-unavailable`.
- `WorkspaceRecommendationsProvider` interface
  (`getRecommendations(handle, {jobId, extractionId,
  profileVersionId})` → ok/recommendations \|
  `extraction-not-ready`/`storage-unavailable`) is D's adapter
  contract. B's route wires a pending provider that always
  reports not-ready: empty drafts stay saveable with honest null
  snapshots; anything needing a snapshot fails closed 409. **D
  swaps the one import in the workspace route.**
- `listVersionSummaries(handle, jobId, {cursor, limit})` →
  newest-first pages (`VersionSummary[]`, `nextCursor`), ≤4
  statements per page, frozen steering names first with live
  lineage fallback, null when unresolvable, `selectedApproved` /
  `latestPublished` from the job pointers. Bad limit/cursor →
  `invalid-request`; corrupt review state/timestamps →
  `storage-unavailable`. Never loads artifact bodies.

## 4. HTTP APIs

Base: `/api/jobs/:id/tailoring`. All responses carry
`Cache-Control: no-store`; all failures use ErrorBody.

- `GET .../workspace` → 200 `WorkspaceReply` + `ETag`
  (`"tw:{job}:{rev}"`, rev 0 when absent); 400/403/404/503.
- `PUT .../workspace` → 201 created / 200 updated, both with
  `WorkspaceReply` + new ETag. Requires exactly one If-Match:
  absent → 428 `PRECONDITION_REQUIRED`; wildcard/list/malformed
  → 400; wrong job/revision → 412 `WORKSPACE_CONFLICT`
  (service conflicts carry `currentWorkspaceRevision`).
  Bodies: 128 KiB cap first (413), then JSON (400), then strict
  `WorkspacePut` (400). Service failures map: unknown-job /
  not-found → 404 `NOT_FOUND`; input-stale → 409 `INPUT_STALE`;
  invalid-selection → 422 `INVALID_SELECTION`; storage →
  503 `STORAGE_UNAVAILABLE`.
- `GET .../versions?cursor=&limit=` (default 50, integer 1..50)
  → 200 `{ok, versions, nextCursor}`; malformed cursor/limit →
  400; unknown job → 404; corrupt stored state → 503.
- Shared helpers in `app/api/_lib/tailoring.ts` for E/F reuse:
  `tailoringError`, `tailoringReadGate`/`tailoringMutationGate`
  (Host/Origin/sec-fetch-site → 403 ErrorBody),
  `tailoringPathId`, `openTailoringDatabase` (startup failures →
  500/503 `STORAGE_UNAVAILABLE`), `parseCappedJsonBody`,
  `ifMatchWorkspace`, `workspaceFailureResponse`, `tailoringJson`.

## 5. Per-order notes

- **C (shell):** render from `GET workspace` (null-safe),
  `GET versions`, and existing detail/board reads. Resolver
  inputs available now: revision/`lastSubmittedRevision`,
  request status via existing progress-agnostic reads.
  ETag/`If-Match` + 428/412/409 handling per §4; autosave
  chains on the returned revision. Step-4 version addressing
  uses exact version ids (G extends eligibility).
- **D (recommendations):** implement
  `WorkspaceRecommendationsProvider` (deterministic,
  no provider call) and the `GET .../recommendations`
  endpoint; swap the pending provider in the workspace route.
  Snapshot bytes must be canonical (`canonicalJson`) so W's
  hash equality holds; phrase ids via `phraseIdFor` over
  canonical JD bytes. W already enforces binding/hash/selection
  rules against whatever the provider returns.
- **E (dispatch):** compose G from `markWorkspaceSubmitted` +
  existing queue/request writers + `insertRequestInputs` inside
  one transaction, in FK order (work item → request → inputs →
  stamp). Same-ID resubmission compares submission bytes
  (`hashSubmission`); changed bytes → 409, same bytes → replay.
  One live TAILOR per job is now index-enforced — treat
  violations as 409 `GENERATION_BUSY`, never delete rows to
  force dispatch. v3 queue payloads validate; v1 is refused.
- **F (worker/progress):** emit boundaries with
  `appendProgressFenced` under the live lease tuple only;
  serve progress from `readRequestProgress` (5-statement
  budget, no token in the struct). Strengthen
  renew/complete/requeue with the expiry/current-attempt
  predicate (A5 pins await). Map trigger names to `Failure`
  codes; unknown raws → `INTERNAL`.
- **G (review/assessment):** publish with `insertAssessment`
  in the version transaction; read via `readAssessment` +
  strict `AssessmentV1` parse; version history via
  `listVersionSummaries`. Extend review eligibility to older
  awaiting versions (current code restricts to the active
  pointer). Never invent measures; calculator stays yours.
