Date: 2026-09-16. Scope: technical contracts §§4–6 + §8, acceptance

## 1. What F delivered

- **v3 worker execution** (`src/tailoring/handler.ts`): v3 payloads
  verify through the shared row checks plus the immutable input
  extension (input-hash agreement, strict focus/recommendation
  parsing, input/v2/v3 hash recomputation, master-text hash, and
  keyword/guidance projection agreement). Every disagreement is
  `INPUT_STALE` — the fix is a new request, never a retry. v2 runs
  keep byte-identical legacy behavior (prose pairs, no emission, no
  timer, exhaustion-only terminal moves).
- **Real stage boundaries** (F4): seq 1 after valid inputs, seq 2–4
  at the orchestration provider/validation/render boundaries, seq 5
  after staged artifact validation — all through `appendProgressFenced`
  with per-attempt source tags. Analysis-only crashes resume from the
  strictly restored proposal with 0 provider calls; original analysis
  lineage is preserved while the resume binds the publishing attempt.
- **Live-lease discipline** (F6): one renewal timer per orchestration
  at `min(30s, floor(lease/3))`; every v3 persist is preceded by a
  liveness check; `LeaseLostError` aborts write-free; publication
  fences on the live lease tuple plus the still-active profile
  version inside the attach transaction. Dispatcher preserves the
  handler `terminal` flag and passes `leaseDurationMs` to handlers.
- **Transaction R** (`src/server/retries.ts`): attempt-specific
  explicit retry. Replay (later attempt, or already requeued/running)
  precedes every check and writes nothing. Otherwise R requires
  current inputs, a retryable terminal failure, job CAS, and no other
  live run, then requeues through `requeueWorkItem` (budget extends,
  numbering preserved, old attempts untouched), marks the request
  QUEUED (error cleared; evidence stays on the attempt row), and
  marks the job PENDING.
- **Progress GET** (`src/server/progress.ts` + route): committed
  version wins (including dedupe convergence onto a same-job,
  same-bytes version, resolved in the same single statement);
  RUNNING/QUEUED from live queue state; QUEUED retains the latest
  failed attempt's evidence; terminal FAILED carries the typed
  failure; legacy/corrupt error text degrades to INTERNAL with the
  persisted timestamp. `retryAllowed` is advisory; R re-enforces.
- **Step 3 UI** (`components/tailoring/Step3Progress.tsx`): persisted-
  attempt elapsed clock with server resync, 2s/10s visibility-aware
  polling that stops at terminal states, lease-expiry recovery
  framing, stage-2 slow-call note, typed failure panels with real
  actions (retry / AI settings event / profile link / back to focus),
  and allowlisted expandable diagnostics with copy. Reads only until
  the human presses Retry.

## 2. Seams G inherits

- **ProgressReply states**: `SUCCEEDED` guarantees a committed
  `resumeVersionId` (own or deduped); `FAILED` guarantees a typed
  `failure` with `code/stage/occurredAt/action`; `RUNNING` carries
  `leaseExpiresAt`/`lastHeartbeatAt` or nulls. `attemptId` names the
  latest attempt for retry observation.
- **Failure codes/actions** (`FAILURE_ACTIONS`): `retry` 7 codes,
  `edit_focus` 2, `open_settings` 3, `edit_profile` 1, `wait` 1.
  Explicit-only codes (no auto-retry): INPUT_STALE,
  PROFILE_UNAVAILABLE, CONFIGURATION, AUTHENTICATION, LOCAL_LAUNCH,
  CLAIM_VALIDATION. Retryable (R-eligible): all except INPUT_STALE
  and PROFILE_UNAVAILABLE.
- **Dedupe convergence**: a rerun deriving identical bytes reuses
  the existing version (no new row); progress reports the converged
  version id. G must not assume `generation_request_id` linkage for
  every successful request.
- **Assessment boundary**: F creates analyses/versions only —
  `resume_assessments` stays empty (asserted 0 in the crash-recovery
  spec). G repeats that spec requiring assessment 1.
- **Step 3 → Step 4**: success panel navigates to step 4; the
  approval pointer (`selected_resume_version_id`) stays null through
  every F flow — only human review sets it.

## 3. Decisions and deviations

- Malformed server replies degrade to failed polls (then `Status
  unavailable`), never to a failure panel: B's strict `ProgressReply`
  schema plus DB timestamp CHECKs make corrupt timestamps unreachable
  from real rows, and `elapsedSecondsFor` still nulls invalid/future
  inputs as defense in depth (unit-pinned).
- R's earlier-observation rule follows §4.1 R text (200 replay),
  not the §4 table's `409 attempt` shorthand: replay precedes every
  check including CAS.
- Legacy (v2, input-extension-less) requests answer 422 through R
  rather than a forged workspace revision; they keep the legacy
  retry route until H cuts over.
- `RELEASED` jobs answer 422 (a retry could never attach); exhaustion
  without a terminal move records recovery-side `LEASE_LOST` with a
  versioned envelope on v3 requests.
- `ReasonCode` widened with the 13 v3 failure codes plus `LEASE_LOST`
  (recovery-side only; a lease-losing worker persists nothing). The
  exact-values enum test now pins the full set.
- Contract-test fallout flipped to the F lease contract (all
  pre-existing wall-clock assumptions, none behavioral): A5 F6 pins,
  B4 progress-fence completion, backup-v13 finish, queries attempts,
  versions service/route finishes, enums, and the persist purity
  import (lease fence uses raw SQL — no Drizzle in `persist.ts`).

## 5. Generation checkpoint (for product testing)

1. Open a NEW job → `/jobs/:id/tailor` → Step 1 shows the retained
   JD; master preview exact.
2. Step 2: apply the preset, edit, submit → generation request
   queued (202, no provider call from the route).
3. Step 3: watch `Ns elapsed` climb through the 5 stages; hide the
   tab 5s and return — the clock catches up without jumping.
4. Stop the provider mid-run (kill the sidecar / break the argv) →
   typed failure panel with the documented title + action; repair,
   press Retry → the same inputs resume and publish.
5. Step 4 (G): the published version awaits human review; nothing
   is approved by the run itself.
